# 代码检测工具改进计划

## 问题分析

通过分析代码检测工具的实现，我发现了以下问题：

### 1. 全局变量滥用

* 多个文件中使用全局变量存储正则表达式模式（如 `cFuncPattern`、`pythonFuncPattern` 等）

* `knownConstants` 全局变量存储已知常量值

* 这些全局变量可能导致并发安全问题，不符合依赖注入最佳实践

### 2. 代码重复

* 不同语言的检测函数结构相似，存在大量重复逻辑

* 例如 `detectCFunctions`、`detectPythonFunctions`、`detectJavaFunctions` 等函数

### 3. 正则表达式模式不够准确

* 一些正则表达式可能无法处理所有边界情况

* 例如 Java 函数检测可能无法处理复杂的泛型和数组类型

### 4. 函数结束位置检测不准确

* Python 函数结束位置检测可能无法处理复杂的缩进情况

* C/C++ 和 Java 的大括号匹配可能存在嵌套结构处理问题

### 5. 测试覆盖不足

* 测试文件主要覆盖基本功能，缺少边界情况测试

## 改进计划

### 1. 重构全局变量

* 将正则表达式模式从全局变量改为结构体字段

* 将 `knownConstants` 移到 `InaccurateConstantRule` 结构体中

* 确保所有依赖项通过构造函数或方法参数注入

### 2. 提取公共逻辑

* 创建通用的函数检测框架，减少代码重复

* 提取公共的辅助函数，如大括号匹配、缩进处理等

* 设计统一的语言检测接口，便于扩展新语言支持

### 3. 改进正则表达式

* 优化现有正则表达式，提高准确性

* 添加更多边界情况的处理

* 考虑使用更强大的解析方法，如状态机或语法分析器

### 4. 增强函数结束位置检测

* 改进 Python 函数结束位置检测，处理复杂缩进

* 优化大括号匹配算法，正确处理嵌套结构

* 添加更多测试用例验证检测准确性

### 5. 增加测试覆盖

* 添加边界情况测试，如复杂函数定义、嵌套结构等

* 增加不同语言的测试用例

* 确保测试覆盖所有检测规则和功能

## 预期效果

通过这些改进，代码检测工具将：

* 更加健壮，能够处理更多复杂情况

* 更加可维护，减少代码重复和全局状态

* 更加准确，减少误报和漏报

* 更加可扩展，便于添加新的检测规则和语言支持

## 实施步骤

1. 重构全局变量为结构体字段
2. 提取公共逻辑到通用函数
3. 改进正则表达式模式
4. 增强函数结束位置检测
5. 增加测试覆盖
6. 运行测试验证改进效果
